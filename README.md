# 每日食记 · Dayly Food

面向国内饮食场景的智能饮食记录 App（Android）。

本地优先 · 无账号 · 自带大模型 Key · 中文食物库

---

## 为什么做这个

国外开源同类产品基本没有国内常见食物的数据库，数据也不完整；国内几个则多为半成品——尤其 AI 部分，只是接了个 API 当聊天助手：没有角色设定、没有提示词边界、不记录上下文，所以识别结果不可用。

这个项目的目标很具体：**把"拍照 → 认菜 → 定份量 → 记入当日 → 对标目标"这条链路做准**，而不是做一个会聊天的记录本。

## 目标功能（MVP）

- 拍照 / 相册 → 多模态模型识别菜品与份量 → 本地食物库匹配 → 用户确认 → 记入当日餐次
- 个人信息 → BMR（Mifflin-St Jeor）→ TDEE → 每日热量与三大营养素目标
- 本地中文食物库：含中式餐具份量（碗/盘/份/串/杯）、国内连锁品牌单品、常见家常菜
- 库里没有的食物：AI 联网兜底 → 数值校验 → 用户确认 → 入库，下次直接命中
- **无 Key / 无网络时，核心记录功能完全可用**

## 关键设计取舍

| 决策 | 原因 |
|---|---|
| 纯本地 + 自带 Key，不做后端 | 隐私最强、零运营成本；代价是无法远程迭代提示词，所以供应商做可切换抽象 |
| 库优先，AI 数值只作旁注 | 数据库是唯一事实源，避免 AI 幻觉污染历史记录 |
| 份量必须用户确认 | 一碗/一盘客观上不可测，假装全自动准确只会让用户失去信任 |
| Room + FTS4 + 自建中文 n-gram 索引 | `unicode61` 分词器对中文失效，`MATCH "米饭"` 搜不到"黄焖鸡米饭" |

## 技术栈

`Kotlin` · `Jetpack Compose` · `Room + FTS4` · `CameraX` · `Hilt` · `OkHttp + kotlinx.serialization` · `minSdk 26`

AI 侧统一走 OpenAI 兼容协议，预设阿里百炼 / 智谱 GLM / 月之暗面 / 火山方舟，支持自定义 BaseUrl。

## 隐私

API Key 通过 Android Keystore（AES-GCM）加密保存，不备份、不写日志。图片仅在识别时上传到用户自己选择的模型服务商，本项目无自有服务端。
